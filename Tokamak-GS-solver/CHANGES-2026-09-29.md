## 2. Green's function (elliptic-integral parameter)

| File | Before | After | Why |
|---|---|---|---|
| `src/numerical/compute.py` `GreenFunction` L13–31 | `k = sqrt(k²)`, `ellipk(k)`, `ellipe(k)` | `k2 = 4RR0/((R+R0)²+(Z−Z0)²)`, `ellipk(k2)`, `ellipe(k2)` | `scipy.special.ellipk/ellipe` take the **parameter m = k²**. See the error sizes below. |
| `src/numerical/compute.py` `GreenFunctionScaled` L33–40 | same bug | same fix | This function is used by `source.py` and `profiles.py`. `GreenFunctionMatrix*`, `GreenBr/Bz*` inherit the fix. |
| `src/GSsolver/GradShafranov.py` `compute_Green_function` L24–29 | `ellipk(k)`, `ellipe(k)` | `ellipk(k**2)`, `ellipe(k**2)` | Same bug in the PINN copy (used by `model.py` for coil and plasma boundary flux). A comment on the unused derivative helpers states that they assume K(m=k²). |

Size of the old error: `old/new − 1` = +9 % as k²→1 (next to the filament), +42 % at k² = 0.95
(review test loop: coil (1.5, 0.25), point (1.0, 0.0): 3.355e-7 → 2.355e-7 Wb/rad/A), +76 % at k² = 0.89,
×8 at k² = 0.5, and it diverges as k² → 0. For k→0 the correct bracket (2−k²)K−2E ∝ k⁴ is a delicate cancellation,
and evaluating K and E at m = k destroys it. Any flux from distant coils was therefore wrong by orders of magnitude.

New test `tests/test_green.py`:
* Compares against direct `scipy.integrate.quad` of the Biot–Savart vector potential,
  ψ = R·A_φ = μ I Rc R/(4π) ∫cos t dt/|x−x'(t)|, for 5 geometries plus 50 random points. The required relative error is < 1e-6, and the observed error is about 1e-15.
* Checks symmetry G(R,Z;R',Z') = G(R',Z';R,Z) to 1e-12. Convention: G is the flux per radian per ampere, which equals the mutual inductance divided by 2π. It is symmetric with no extra R-weighting. (G/R, the Green's function of Δ* itself, is not symmetric.)
* Runs the same comparison for the PINN copy (skipped if torch or scikit-image is missing).

## 3. Free-boundary solver (`GSsolverFreeBoundary`, `src/numerical/grad_shafranov.py` L360–end)

The public API is unchanged (`__init__`, `solve`, `plotGrid`, and the method names `initializeGrid`, `updatePsi`,
`updateBoundary`, `updateJ_phi`, `getJpBoundary`). The internals were rewritten because none of them could work:

| Aspect | Before | After | Why |
|---|---|---|---|
| Boundary ψ | `psi_b` was one scalar: the mean of positive values on the edges `idx_col==0 or idx_row==0` (2 of 4 edges). It was never imposed as a Dirichlet condition | ψ on **all four edges** = Σ_cells G(edge; R',Z') J_φ dR'dZ' (precomputed `G_edge` matrix) + coil flux | This is the free-boundary condition (FreeGS style, direct Green's integral). |
| Coil | `psi = Ic·G` and a "coil current density" `J = (dBr/dz − dBz/dr)/μ` from finite differences of B (≈ 0 or singular) | ψ_coil = Σ Ic·G(Rc,Zc;R,Z) analytic, added to ψ_plasma. Several coils allowed. A coil inside the grid raises `ValueError` | A vacuum field has no current density. A coil inside the box is singular (NaN on a node). |
| Plasma mask | none (J_φ evaluated everywhere, also with ψ_N > 1 and negative powers) | `mask = (ψ_N < 1) & interior & connected to the axis` (`scipy.ndimage.label`). J_φ = 0 outside | This is the definition of the plasma region. |
| Axis / LCFS | ψ_a = 0 fixed. ψ_b from the averaged edges | ψ_a = extremum of ψ in the interior. ψ_b = extremum of ψ on the box edge (the LCFS is limited by the box) | This gives a consistent ψ_N. |
| Ip | none (λ = λ₀ fixed) | Optional `Ip`: λ rescaled every iteration so that ∫J_φ dA = Ip | Constraint. The smoke test checks it. |
| Linear solve | Dense `GSMatrix` (undefined) + `np.fill_diagonal(-1)` + one Python-loop SOR sweep per iteration, O(N⁴) | Sparse `ElipticOperator('2nd')`, Δ*ψ = −μRJ_φ with Dirichlet rows, factorised once with `splu` | Correctness and speed: 128×128 now takes 0.5 s. The old dense approach needed about 2 GB for the matrix and O(N⁴) Python operations per sweep, which was infeasible. |
| Convergence | `‖Δψ‖₂` absolute | `‖Δψ‖₂ / ‖ψ‖₂` relative, with `converged` and `n_iter` attributes | Scale-independent. |
| `plotGrid` | `meshgrid(arange(Rl,Rr,dr), arange(Zl,Zr,dz))` gives arrays of shape [Nz,Nr], while ψ has shape [Nr,Nz], so **R and Z were swapped** (hidden when Nr = Nz) | `meshgrid(..., indexing='ij')`, LCFS and axis overlay, `set_aspect('equal')`, output folder created | Wrong figure. The same axis fix was applied to the legacy `GSsolver.plotGrid` (L318). |
| Diagnostics | none | `total_current()` = −(1/μ)∫Δ*ψ_p/R dA | Sanity check. |

`test_free_boundary.py` defaults changed: the old default (a 1 A coil at (1.5, 0.25) **inside** the grid, box
Z∈[0, 0.5], no current constraint) cannot give a physical equilibrium. New defaults: box R∈[1,2], Z∈[−0.5,0.5],
`--Ip 2e5`, two coils `--Rc 2.2 2.2 --Zc 0.7 -0.7 --Ic -9e4 -9e4`, `--w 1.0`, `--iteration 256`. The CLI flag names are unchanged,
and `--Rc/--Zc/--Ic` now accept several values.

New test `tests/test_free_boundary_smoke.py` (65×65, about 0.1 s) checks the following:
* Convergence, with a relative change < 1e-8.
* The axis is an interior node near Z = 0 and lies inside the mask.
* ψ_N increases strictly monotonically along 4 rays from the axis up to ψ_N = 1.
* The mask does not touch the edges, and J_φ = 0 outside the mask.
* Total current within 1 % of the target in three ways: ∫J_φ, −∫Δ*ψ/(μR), and **Ampère's law** −∮B_p·dl/μ around the box. The last one is independent of the solver's discretisation (observed 2e-4).
* The edge values equal the Green's-function flux on all four edges.
* `ElipticOperator` (2nd and 4th order) is exact on polynomials it must reproduce.
* A coil inside the domain is rejected.

`result/Free-Boundary-Equilibrium-fixed.png` was regenerated with the new defaults. The old
`result/Free-Boundary-Equilibrium.png` was kept unchanged; it shows the old, incorrect result.

## 5. Not fixed (known limitations)
* No X-point search, limiter contour or coil feedback. The LCFS is limited by the rectangular box. Picard without position
  control is unstable for many coil sets (the plasma drifts to the wall).
* No β_p constraint in the free-boundary example. β₀ is fixed.
* Legacy fixed-boundary path (`test_boundary.py`, `tokamak.py`, `GSsolver`, `profiles.py`, `boundary.py`): it imports now,
  but it still fails at run time (`ValueError` in `boundary._update_psi_a`: no axis found) and uses dense O(N⁴) loops.
* `train_PINN.py`, `test_PINN.py` and `src/eqdsk/eqdsk.py` still emit `SyntaxWarning`s for strings such as `'\PCPF1U'`. These are
  data column names and were left unchanged.
