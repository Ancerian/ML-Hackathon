# C2 — попередня реєстрація (записано 2026-09-30, ДО навчання будь-якої моделі)

Файл не редагується після запуску. Відхилення фіксуються в `../findings.md` («Перевірка C2»).
Вибір користувача: метрика — Consistency + S; моделі — PCA+Ridge і UNet_Lite; дані — розбиття
`SCORE.md` (40 + 8); контролі — H¹, перемішана вага, переміряна S(k); пласка MSE — база порівняння.

## 0. Твердження

**C2** (`00-decisions/CONJECTURES.md`): спектрально зважена втрата, виведена з кривої S(k) (D1,
результат 3), **покращує реальні моделі**. Спростує: бейзлайн, навчений із нею і без неї, має
однаковий S′.

**Уточнення формулювання.** S′ (`04-novelty/metric-design.md`) не реалізовано: член Calibration
потребує невизначеності, якої бейзлайни не видають. Тому міряємо офіційними членами:
- **головна метрика — Consistency** (середнє R² семи похідних скалярів). Саме на неї цілить S(k);
- **друга — композитний S** офіційного скорера (`local_score.py`, v3.1): вага не повинна
  купувати Consistency ціною R²ψ, бо R²ψ має в S вагу 0,55;
- **звітуємо також** R²ψ, 1 − D_LCFS і R² кожного з семи скалярів.

## 1. Що відомо заздалегідь (ризики)

- S(k) у D1 виміряно при e = 0,1 (R²ψ = 0,99) на 3 демо-розрядах. Реальний PCA+Ridge на
  відкладених розрядах має R²ψ = 0,064 (`SCORE.md`), тобто e ≈ 0,97. Робоча точка інша.
- R10 (C1): властивості, виміряні на 3 демо-розрядах, можуть не переноситися. Тому S(k)
  переміряємо на 28 розрядах (`../c1/`, ті самі функції D1).
- У PCA+Ridge кожен вихід навчається незалежно, тож зважування втрати **саме по собі** нічого не
  змінює. Вага діє лише через **зважену PCA**: базис будується у просторі ψ̃ = F⁻¹(√w·F ψ).
  Для UNet_Lite вага діє прямо у втраті.

## 2. Вагові схеми (4 «руки»)

Кільця хвильових чисел — ті самі, що в D1: [1,2), [2,4), [4,6), [6,9), [9,13), [13,18), [18,24),
[24,32]; |k| < 1 отримує вагу першого кільця, |k| > 32 (кути спектра) — вагу останнього.
k — радіальне хвильове число на сітці 65×65 (`numpy.fft.fftfreq(65)·65`).

1. **flat** — w ≡ 1 (звичайна MSE / звичайна PCA).
2. **S(k)** — S_j(b) = медіанна похибка скаляра j (в одиницях σ_j) при смуговому збуренні в кільці b
   з амплітудою e_op (п. 3), на 28 розрядах DIII-D (`c1/sweep_core`, оцінювач D1).
   w_b = середнє по семи скалярах від S_j(b) / max_b S_j(b).
3. **H¹** — w(k) = 1 + (k/k_c)², k_c вибрано так, щоб max/min по центрах кілець збігався з
   max/min для S(k). Та сама «сила» зважування, фізично нейтральна форма.
4. **shuffled** — ті самі 8 значень w_b, переставлені випадково (`numpy.random.default_rng(0)`);
   якщо перестановка тотожна — наступна з того самого генератора.

Усі ваги нормуються так, щоб середнє w по всіх 65×65 хвильових векторах дорівнювало 1
(за Парсевалем втрата лишається в масштабі MSE).

## 3. Робоча точка e_op

e_op = √(1 − R²ψ) пласкої PCA+Ridge на **валідаційних** розрядах (потокові № 36–39, у навчання не
входять). S(k) переміряємо при e ∈ {0,1; 0,3; 1,0}; для ваги беремо e, найближче до e_op у
логарифмічній шкалі. Криву при e = 0,1 (як у D1) звітуємо окремо для порівняння.

## 4. Навчання й оцінка

- Навчання: потокові розряди № 0–35; валідація: № 36–39 (лише для e_op і планувальника швидкості
  навчання); тест: № 60–67 (розбиття `SCORE.md`, у навчанні й валідації не бере участі).
- Ознаки: 21 струм котушок (`baseline_pca_ridge.features_for_row`), StandardScaler.
- PCA+Ridge: 50 компонент, Ridge α = 1 (як у `SCORE.md`). Детермінований, 1 прогін на руку.
- UNet_Lite (`experiments_torch.py`): ψ нормовано однією середньою й σ; Adam, lr 10⁻³, batch 256,
  50 епох, ReduceLROnPlateau за валідаційною втратою **своєї** руки; модель — остання епоха.
  3 зерна (0, 1, 2) на руку.
- q95 і βN для S — той самий Ridge у всіх руках (вага їх не стосується).
- Оцінка — функції `local_score.py` (`build_reference`, `score_shot`, `finalize_machine`).

## 5. Невизначеність

Парна різниця Δ = рука − flat. Бутстреп 1000× по **тестових розрядах** (для UNet — з усередненням
по 3 зернах усередині кожного повтору). 95 % інтервал Δ.

## 6. Критерії вердикту

**C2 ПІДТВЕРДЖЕНО** — для **обох** моделей: ΔConsistency(S(k) − flat) > 0 з 95 % ДІ, що не
містить 0; ΔS ≥ −0,01; і S(k) краща за **обидва** контролі за Consistency (точкова оцінка), причому
для хоча б однієї моделі ДІ Δ(S(k) − кращий контроль) не містить 0.

**C2 СПРОСТОВАНО** — для обох моделей ДІ ΔConsistency(S(k) − flat) містить 0 або лежить нижче 0.

**УТОЧНЕНО / ЧАСТКОВО** — усі інші випадки, зокрема:
- покращення лише для однієї моделі;
- покращення є, але H¹ чи shuffled не гірші (тоді допомагає зважування взагалі, а не форма S(k));
- Consistency зростає, а S падає більше ніж на 0,01 (вага купує скаляри ціною R²ψ).
Кожен такий випадок записуємо з числами; C2 у початковому формулюванні тоді закривається
як R-запис, а встановлене — окремим E-записом.
